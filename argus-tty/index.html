One package to onboard an SSH account and make its sessions impossible to not record.

argus-tty provisions developer/admin/deployer Linux accounts on a shared Ubuntu host and forces every one of their sessions through a TTY recorder via sshd's own ForceCommand — logs ship to S3, with an email ping on connect/disconnect.

Launchpad PPA .deb package MIT licensed GitHub

The problem argus-tty solves isn't "how do I let a team SSH into a box" — that's one line in authorized_keys. It's "how do I do that and still answer, after the fact, exactly who ran what, when, and what the session actually contained" — without a single shared root account that nobody can attribute to a person. Every onboarded account is a real Linux account, in one of three tiers, and every one of them — developer, admin, or deployer, no exceptions — has its session forced through a recorder by an sshd Match block that a user's own ~/.ssh/authorized_keys cannot override. 

sudo add-apt-repository ppa:yadavramlaxman/argus-tty
sudo apt update && sudo apt install argus-tty   # or the .deb package — see Installing below

sudo argus-tty add dev1 --name "Alice Kumar" --pubkey dev1_id_ed25519.pub
sudo argus-tty status   # confirm sshd/sudoers/systemd are all wired up

Full install guide, including the .deb-package alternative and bulk onboarding: Installing argus-tty.

What it does

  • Three Linux account tiers, each individually attributable — developer (scoped sudo via a command whitelist), admin (full, unrestricted sudo, onboard sparingly), and deployer (the narrowest tier: start/stop/restart services only). No tier is a shared account.
  • Recording nobody can opt out of — the sshd Match Group developer,admin,deployer block's ForceCommand always wins over anything in a user's own authorized_keys, so every session, admin sessions included, is captured as a full TTY transcript (script) plus command history.
  • Three privilege-separated helpers, not one process that does everything — argus-tty-wrapper (runs as the connecting user, records the session, never touches credentials), argus-tty-finalize (same uid, uploads to S3 via the instance's IAM role — no access keys on disk), and argus-tty-mailer (root-only, the only process that ever reads the SMTP password). See why they're split this way.
  • Everything optional and non-blocking — S3 upload and email are both off by default and gated by their own master switch; local session recording to disk always happens regardless of whether either integration is configured or reachable.
  • Optional Google Authenticator 2FA — a second factor on top of the SSH key for developer/admin sessions, with deployer accounts always exempt.
  • A real, upgradable .deb — apt install/ apt remove/apt purge to a fleet, not scp -r and hope; a PPA so upgrades arrive via ordinary apt upgrade.
