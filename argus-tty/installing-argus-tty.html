Installing argus-tty

Launchpad PPA (recommended) or the standalone .deb package, onboarding your first accounts, and verifying the install.

Option A — Launchpad PPA (recommended)

sudo add-apt-repository ppa:yadavramlaxman/argus-tty
sudo apt update
sudo apt install argus-tty

Same package as the .deb below, just distributed through Ubuntu's normal apt/PPA mechanism — upgrades arrive via your regular apt upgrade instead of re-downloading a file by hand. See PACKAGING.md if you want to build and publish your own PPA from source instead of using this one.

Option B — the .deb package

scp dist/argus-tty_1.0.11_all.deb root@host:/tmp/
ssh root@host
sudo apt install /tmp/argus-tty_1.0.11_all.deb   # pulls openssh-server/sudo/curl/etc. if missing

apt install unpacks every file to its canonical location and automatically runs the same configuration install.sh used to run by hand: creates the developer/admin groups, locks down the three installed binaries, wires up PAM/sudoers/the sshd Match block, and enables/disables the mailer timer to match EMAIL_ENABLED (false by default). At the end it prints the three follow-up commands you actually need to run: 

sudo vi /etc/argus-tty/config.env            # S3_BUCKET, AWS_REGION, EMAIL_TO/FROM, SMTP_HOST/PORT
sudo vi /etc/argus-tty/smtp-credentials.env  # SMTP_USER/SMTP_PASS — root-only, 600
sudo argus-tty reconfigure                   # re-applies config + re-validates sshd/sudoers/systemd

Upgrading: sudo apt install ./argus-tty_<newer>_all.deb — dpkg preserves your edits to config.env/smtp-credentials.env (real conffiles). Removing: sudo apt remove argus-tty stops the mailer and removes the sshd Match block (so onboarded accounts keep working over plain, unrecorded SSH instead of breaking outright) — it never touches onboarded Linux accounts, home directories, or the audit trail already written under /var/log/argus-tty/.

Onboarding your first accounts

# One developer, key from a file:
sudo argus-tty add dev1 --name "Alice Kumar" --pubkey dev1_id_ed25519.pub

# No key provided — a PEM keypair is generated for them automatically:
sudo argus-tty add dev2 --name "Bob Singh"

# Admin (full sudo, same recording pipeline):
sudo argus-tty add-admin admin1 --name "Carol Diaz" --pubkey admin1_id_ed25519.pub

# Deployer (narrowest tier: start/stop/restart only):
sudo argus-tty add-deployer deploy1 --name "Eve Ortega" --pubkey deploy1_id_ed25519.pub

# Many at once — see developer_users.conf.example for the roster format:
cp /usr/share/doc/argus-tty/developer_users.conf.example developer_users.conf
sudo argus-tty bulk-add developer_users.conf

add/add-admin/add-deployer are all idempotent — re-running one for an existing username just ensures group membership and installs whatever key you passed; it never duplicates the account or overwrites a key that's already there.

Verifying the install

sudo argus-tty status   # health check: sshd config, mailer timer, aws cli, S3, SMTP, disk usage

Then, from a new terminal (don't close the one you're using to make changes):

ssh dev1@<host>                 # connects, banner shows "all commands are recorded"
sudo systemctl status ssh       # allowed (whitelisted)
sudo su                         # denied
exit                            # disconnect — check S3 for the session files and your inbox for the email

S3_UPLOAD_ENABLED and EMAIL_ENABLED both default to false — a fresh install never attempts an AWS or SMTP call until you've filled in that integration's config and flipped its switch in config.env. Session recording to local disk under /var/log/argus-tty/sessions/ always happens regardless.
